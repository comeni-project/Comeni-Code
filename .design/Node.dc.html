The problem it solves

A sequencer does not read a genome from end to end. It returns millions of short pieces — reads — sampled from random positions, overlapping each other, in no order. Putting them back together is assembly; finding where they came from is indexing. Both need a way to use overlaps without comparing every read with every other read, which grows with the square of the number of reads.

From reads to k-mers

The trick is to stop treating reads as units. Slide a window of width k along each read and record every substring it covers: these are the read’s k-mers. Two reads that overlap share k-mers, so overlaps can be found by looking k-mers up in a table instead of aligning reads to each other.

Building the graph

Now connect the k-mers. Draw an arrow from one k-mer to another when the last k−1 letters of the first are the first k−1 letters of the second. Every read becomes a path, and reads that overlap share part of their path. Walking along the arrows spells sequence back out: each step adds one letter.[1]

Formal definition

{% math %}
Given reads R and an integer k, the de Bruijn graph Gk(R) = (V, E) has
  V = { (k−1)-mers of R },   E = { k-mers of R },
  and each k-mer x1…xk is an edge x1…xk−1 → x2…xk.

A sequence consistent with the reads is a walk in Gk. A walk that uses every edge exactly once is an Eulerian path, which can be found in linear time — the reason this formulation displaced overlap-graph approaches that lead to the much harder Hamiltonian path problem.[1]

Two conventions

Papers, tools and textbooks disagree on what a node is. Read a paper’s definition before comparing numbers across it and another.

Errors and repeats

Real reads contain sequencing errors. An error creates k-mers that exist in only one read, and they leave recognisable shapes: a bubble when the wrong base is in the middle of a read and the path rejoins, a tip when it is near an end and the path dead-ends. Assemblers remove both. Repeats longer than k do the opposite: they merge distinct parts of the genome into one path.

Cost and choosing k

With a hash table, building the graph takes expected time linear in the total number of k-mers; memory is dominated by the number of distinct k-mers, which is why real tools compact unbranched paths into single nodes — the form Salmon’s index uses.[2] A larger k resolves more repeats but breaks the graph wherever coverage is low or reads contain errors; a smaller k keeps it connected but tangles repeats together.
