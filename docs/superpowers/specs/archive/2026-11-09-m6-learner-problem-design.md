# M6.8a — The learner's problem

**Status: draft 2026-11-09.** Part of M6.8 (#335), issue #423. Designed with the operator on
2026-11-09, from the boards at https://claude.ai/artifact/NQcPg7GbVi5pEAhJeszewF (`NodeProblem`,
generated by `.design/build_pages.mjs`'s `nodeProblem()`). Builds on M6.7
(`2026-11-07-m6-problems-design.md`, M6PR.1–M6PR.7): the kits, `problem.yaml`, `NodeProblem` in
the index. The builder (S5) is M6.8b (#424).

## What it does

A node's problem is drawn on its page where its `:::{problem}` block sits: the statement, Given and
Return, the sample computed by the kit, hints, **a dataset of the learner's own** to download, and
one answer to send. The server makes the dataset from a seed, checks the answer, and answers right
or not, the kit's one sentence, the misconception callouts the answer's mistakes point to, and the
rationale once right. Nothing about the learner is stored.

**In:** the learner's problem in `GET /api/nodes/{id}`; `GET …/problem/dataset` and `POST
…/problem/answer`; a seed per browser; `node/Problem.tsx`; the sample's size limit; CA0009–CA0012.

**Out, and where it goes:** the builder (M6.8b, #424); solved state, % solved and solutions (learner
records, M8); the step back from a callout to a page (`step_back_to`, M8); authors' own mistakes and
kits (#425, deferred); a rate limit on answers (open, below).

## M6LP.1 The seed: one per browser

- The page keeps **one seed per browser** in `localStorage` (`comeni.problem-seed`), made on the
  first problem it draws with `crypto.getRandomValues`: 64 bits, written as decimal digits. One
  seed serves every problem; two problems never share a dataset since their kits or params differ.
- Storage blocked or emptied: a seed made for the page's life, so a reload gives a new dataset. The
  page says nothing about it; nothing is lost but the download.
- **The seed travels as a string** (`^[0-9]{1,20}$`, below 2⁶⁴, else 422 CA0011): a JSON number
  above 2⁵³ loses digits in JavaScript.
- *Why per browser:* M6's *done when* needs the problem working, and learner accounts are M8's.
  At M8 the account supplies the seed; the endpoints keep their shape. Rejected: waiting for
  accounts (holds M6); a seed made by the server and kept in a cookie (state on the server for no
  gain: the seed is worthless without solving).
- A learner can pick any seed, including another's. That is fine: an answer is still computed by
  solving, and the server never sends one.

## M6LP.2 The problem in the node's API

`NodeOut` gains `problem: LearnerProblemOut | null`, and its `blocks` stop leaving the block out:
the `{kind: "problem"}` block (M6.7's `ProblemBlockOut`) is sent in its place.

`LearnerProblemOut`: `title`, `rung`, `statement` (Markdown with formulas), `given`, `returns`,
`sample_dataset`, `sample_output`, `hints`, `callouts` (the titles mistakes map to, so the page
knows which of its callouts can be named), `kit`, `version`, `size` (the kit's `cost` at the
problem's params, in bytes: "about 2.5 KB").

Not sent: `params`, `mistakes`' names, the rationale (only with a right answer), the file's text.

**`version`** names what a dataset is made from: the first 12 hex digits of the SHA-256 of the
problem's text **and** the kit's own run at seed 0 (its dataset and its answer), computed in the API
(`code-schema` has no `hashlib`) and kept per text within a process. A deploy that changes a kit's
`generate` or `solve` restarts the processes and changes the version, so a learner's old file gets
409, never a silent *wrong*. A kit's change that leaves seed 0 alone and changes another seed is
missed; the kits' pinned-seed tests are what catch that. *My call, after the builder check: the
text alone missed a changed kit.*

Read with `stored_problem` (#420): no self-test on read.

## M6LP.3 The dataset

`GET /api/nodes/{id}/problem/dataset?seed=<digits>&version=<hex>`

- 200 `text/plain; charset=utf-8`, `Content-Disposition: attachment; filename="<kit>-<seed>.txt"`,
  `Cache-Control: private, max-age=86400`: the same URL always gives the same bytes.
- **The page's Download fetches it** (`getText`, one request) and saves the text through an object
  URL, so an error reaches the page as a sentence (409 is M6LP.5's) instead of being saved as the
  file. *My call, after the builder check: a plain link saved a JSON error as `<kit>-<seed>.txt`.*
- 404 CA0002 (no node), 404 CA0009 (the node has no problem), 409 CA0010 (`version` is not the
  problem's: it changed since the page was read), 422 CA0011 (a seed not as M6LP.1 says), 503
  CA0001.
- The kit runs in the request (`generate`, at most `max_bytes`: 120 KB, ~0.2 s at the largest
  params). No Celery: a learner waits for a file either way.

## M6LP.4 The answer

`POST /api/nodes/{id}/problem/answer {seed, version, answer}` → 200
`{right, said, callouts: [title], rationale}`

- The server generates the dataset, solves it and runs the kit's `check`: `right`, `said` (one
  sentence, counts never the answer), `callouts`: the titles the file maps the verdict's mistakes
  to, in the order of the kit's `mistakes` (the API sorts: a checker may name them in another
  order), each title once; `rationale` only when right, else `null`.
- **The answer is never sent to the page**, nor the dataset again.
- `answer` at most 1 MB (the largest allowed problem's answer is ~660 KB), else 422 CA0012; the
  rest as M6LP.3 (CA0002, CA0009, CA0010, CA0011, CA0001).
- No auth and no CSRF token: it changes nothing, as the learner's other routes take no auth.
- Run in the request (~0.2 s at the largest params; the fixture's ~1 ms).
- A kit raising on a learner's answer is a bug: the server logs it and answers 500, and a test
  per kit feeds it garbage (#418's lesson).

## M6LP.5 The page (`node/Problem.tsx`)

As the board draws it:

- The block's place in the body; a heavy-bordered panel: *Proves this node*, the title, a rung tag
  (*Rung 1 · read it off the file*, *Rung 2 · one command*, *Rung 3 · a few lines of code*, *Rung 4
  · it has to be efficient*: §5.1.1's rungs in the learner's words), the statement,
  Given and Return as text, the sample dataset and output in monospace boxes that scroll sideways.
- **Hints** one at a time (*Show a hint (2)*), as a try's.
- **Your dataset**: the file's name, *about 2.5 KB*, *made for this browser, so its answer is yours
  alone*, and Download.
- **Your answer**: a text area and *Choose a file*, read in the browser (`File.text()`) into the
  area; over 1 MB is refused there with a sentence, before any request. Submit sends one POST.
- **Verdict**, `aria-live`: wrong is *Not yet* and `said`; each named callout quoted (its kind tag,
  title and text, from the page's own blocks) with *Read it in the page ↑*, which scrolls to it;
  *Your dataset stays the same: fix your answer and send it again.* Right is *Right* and *Why:* the
  rationale.
- **409 CA0010**: *This problem was updated after you downloaded your dataset. Download it again.*
  The page refetches the node (its `version` changes), so the next Download is the new problem's.
- After a reload the problem is unanswered again: no state is invented (now.md: *absent, not
  faked*).
- At 390 px the boxes stack and the rung tag goes under the title; nothing scrolls the page sideways.
- One mutation in `api/queries.ts` (`useProblemAnswer`), no query: nothing is cached or refetched.
- **In Studio** (the workbench's preview and Review's block panel draw drafts through the same
  `Body`): the panel is drawn without the dataset and the answer, as the S5 board's preview is (*Each
  learner downloads their own here*), since a draft is in no index and has no version. `Problem`
  takes the problem as a prop, and its live part only with a `{node, version}` the learner's page
  passes; a draft's `node.problem` is sent in `LearnerProblemOut`'s shape without `version`. *My
  call, after the builder check.*

## M6LP.6 The sample's size

A sample is drawn on the page, so its `cost` must be at most **2,000 bytes** (CS1102, the path
`sample.params`), checked in the self-test before it runs. Today it may reach 120 KB (#421). The
fixture's sample is 18 bytes.

## M6LP.7 Codes

CA0009 the node has no problem · CA0010 the problem changed since your dataset was made · CA0011 a
seed is not a whole number below 2⁶⁴ · CA0012 an answer over 1 MB. Each in `diagnostics.yml` with
`explain` and a test.

## M6LP.8 Done when

1. The de Bruijn fixture's page draws its problem as the board does, in the four states and at
   390 px, light and dark, walked in a browser on the Compose stack.
2. Two downloads with one seed give the same bytes; two seeds give different files.
3. A right answer (the solver's output for the downloaded file) is *Right* with the rationale; a
   duplicated line names *Every edge appears once* and quotes it; a missing edge gives the sentence
   alone; a stale `version` gives 409 and the page's sentence, on Download and on Submit.
4a. A draft's preview draws the problem with no Download and no answer.
4. The answer is in no response; the rationale is in none but a right one.
5. Each CA0009–CA0012 and the sample's CS1102 is produced by a test.

## Decisions, and the alternatives rejected

- **A seed per browser** (M6LP.1). Rejected: waiting for accounts; a server-kept seed.
- **The server generates and checks; the browser only downloads and sends.** Rejected: a kit
  twinned in TypeScript (M6.7 rejected it: every learner's answer would be in their page).
- **`version` on both calls.** Rejected: checking against today's problem silently, which marks a
  learner wrong for an answer to yesterday's.
- **Download fetched, saved through an object URL.** Rejected: a plain link, which saves an error
  as the learner's file.
- **No rate limit yet.** A submit costs ≤ 0.2 s; the cap is the 1 MB body. Open, below.

## Open

- **A rate limit on answers and downloads** (per IP, in Redis) before the site is public.
- **`version` and the index:** a new build that leaves the problem's text alone keeps its version,
  so a learner's file stays good across builds. Intended.
