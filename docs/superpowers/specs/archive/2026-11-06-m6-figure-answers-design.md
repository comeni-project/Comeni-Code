## What it does

A learner answers a question by working the figure: tracing a path through a `kmer-graph`, or
picking a k-mer of a tip or bubble in `graph-artifacts`. The right answer is **computed by the
component** from the figure's data, never typed. A choice option may be a figure. The composer gets
the Interaction step deferred from M6.5 (#332): the task, its four states and the *every state draws*
check.

**In:** the `figure` answer kind in try and exam questions; two tasks (`trace`, `pick`); figures as
choice options in both pools; `marks` on `graph-artifacts`; the Interaction step; the learner's try,
the test question (as the exam preview and review draw it), the reviewer's answer, and grading on the
server; the de Bruijn fixture.

**Out, and where it goes:** seeded variants and the 20-seed check (M6.7's generators, M6.9); tasks for
`read-tiling`, `kmer-window` and `compare-graphs` (added when content needs one, each a reviewed
change, as W5.3's other components are); images as options (when content needs them); the self-test
itself (M8). Figures as exam options were listed for M6.6 in the figures spec and stay here (operator,
2026-11-06).

## M6FA.1 The task is in the figure file

A figure file gains an optional `interact` key, as W5.3 sketched it:

```yaml
component: kmer-graph
alt: A de Bruijn graph of six 3-mers from four reads …
data:
  reads: [{sequence: ACGTT}, {sequence: CGTTA}, {sequence: GTTAG}, {sequence: CGTC}]
  k: 3
  highlight: none
interact: {task: trace, spells: ACGTTAG}
```

- **A figure with `interact` is a question's**: it may be the figure of a `kind: figure` question and
  nowhere else. Placed as a body `figure` block, as the figure above a question of another kind, or as
  an option, it is refused (CS1029). A `kind: figure` question whose figure has no `interact` is
  refused too (CS0338 in a try, CS0824 in the exam pool). *Operator, 2026-11-06.*
- **What is computed** joins `derived` as `answer`: `{accept, wrong}` (M6FA.3). `derived(component,
  data, interact)` in `code_figures` is the one entry; `figure_findings` takes `interact` too.
- `NodeFigure` gains `interact` (JSON, null when absent); `FigureOut` sends it beside `derived`.
- *Rejected:* the task on the question. The composer could not draw the states without the question,
  and the computed answer would join two files in the index.

## M6FA.2 The two tasks

Each kit may declare **tasks**: `code_figures/<kit>.py` gains `TASKS`, a name → `Task` with a schema
for its fields (`schemas/<kit>.<task>.json`), `check(data, derived, fields) → findings` and
`answer(data, derived, fields) → (accept, wrong)` — a Strategy per task, registered with the kit, so
a third task is one entry. The TypeScript twin mirrors it in `kits.ts`, and `cases.json` gains
`interact` cases run by both.

| Kit | Task | Fields | The learner | `accept` | `wrong` (drawn by the composer) |
|---|---|---|---|---|---|
| `kmer-graph` | `trace` | `spells`: letters | clicks k-mers in order, each along an arrow | one selection: the k-mers of `spells`, in order | the path to the first branch, then off it; with no branch, the path less its last k-mer |
| `graph-artifacts` | `pick` | `artifact`: `tip` or `bubble` | clicks one k-mer | each k-mer of every run of that kind, one selection each | a solid k-mer (one exists: CS1015) |

**Checks** (new codes in `diagnostics.yml`, each with a test naming it):
- CS1028 — `interact` names no task of this component, or its fields do not fit the task's schema.
- CS1029 — a figure with a task placed anywhere but as a figure question's figure (M6FA.1).
- CS1030 — `trace`: a k-mer of `spells` is not in the graph, or a step is not an edge a read holds
  (#408's rule), naming the first that fails; `spells` shorter than k + 1; or `spells` holds a k-mer
  twice (a path through a repeat), so each k-mer is picked at most once. *My call*: rejected, letting
  a k-mer be picked again, which a numbered, pressed button cannot show.
- CS1031 — `trace` on a figure with `highlight: path`: it would draw the answer.
- CS1032 — `pick`: the figure has no run of that kind.

`trace` has one right answer by construction (a sequence has one walk of k-mers); `pick` accepts any
k-mer of the kind, and the composer says so.

## M6FA.3 Grading: one rule

**A selection is an ordered list of k-mers.** The learner's selection is right iff it equals one of
`accept`. One rule for both tasks, in `code_schema.grading` and the web's `grading.ts`.

- `code_schema.questions` gains `FigureAnswer` (`kind: figure`, `figure`: the stem, `accept`). **The
  question's figure is the one it already has**: a try's `figure:` key; an exam question's `figure`
  block in its stem, which already places figures (`node.py`), so the exam pool gains no key. A
  `kind: figure` exam question has exactly one figure block in its stem (CS0824 otherwise), and still
  its stem's text (CS0816). CS0306 (*a figure question arrives in M6*) is retired, its number kept.
  *My call, after the builder check.*
- **`accept` is filled when the folder is read.** `code_schema` already reaches `code_figures`
  (`figures.py` checks a figure's data by its component, allowed by the purity guard), so the folder
  read in `node.py`, which holds both the questions and the figure files, sets each `FigureAnswer`'s
  `accept` from `derived(component, data, interact)["answer"]`. `score(answer, given)` and
  `is_right` keep their signatures, and every caller (`review.py`'s `_graded`, `answer` and approval's
  wrong count; later the self-test) grades a figure answer as any other. The web grades from the
  figure record it already receives (`FigureOut.derived.answer`). *My call*: rejected, passing
  `accept` into `score`, which changes three callers for no gain.
- **Where the placement checks run**: CS0338, CS0824 and CS1029 need a question and a figure file
  together, so they run in the folder check in `node.py` beside the figure placement checks;
  `interact` joins the figure file's keys in `figures.py` (CS1025 would refuse it). In the
  workbench they arrive with the draft's verify, as every node-level problem does; the browser twins
  only a task's own findings (M6FA.6), which the composer needs before a save.
- **Options**: an option holds `text` or `figure` (a stem), exactly one (CS0339 in a try, CS0825 in
  the exam pool). Grading is unchanged: an option's index. **Any figure without a task** may be an
  option, of any component; whether it gives the answer away (a `kmer-graph` highlighting its path,
  `graph-artifacts` with its marks shown) is the author's to write and the reviewer's to catch, as
  with an option's text. *My call*.

## M6FA.4 The learner's side (L5, L13)

One component, `FigureAnswer.tsx`, used by `TryQuestion` and `TestQuestion`:

- **Every k-mer is a real `<button>`**, overlaid on the drawing at the layout's coordinates (the
  kits' `graphLayout`), its tap area at least 44 px, larger than its box; `aria-pressed`; Tab follows
  reading order, Enter or Space picks. An `aria-live` line reads the selection back (*ACG → CGT → GTT
  spells ACGTT*; *Your pick TCA*).
- **Asked, the figure gives nothing away**: no highlight, nothing spelled, tips and bubbles unmarked,
  until it is answered (a try: checked right; a test: the results).
- **Trace**: picks are numbered and blue (selected); a pick that does not follow an arrow from the
  last is not taken, and the line says what can come next; the k-mers it can go to are dashed. Undo
  and Clear beside Check. **Pick**: one k-mer, Clear.
- **The four states**: start; midway; wrong answer (a try: red, the selection kept, the next hint,
  as the other kinds); answered (the computed answer in teal: the path, or the run with the marks).
- **Phone**: the drawing keeps three quarters of its width and scrolls sideways, as #402 decided.
- **Figure options**: a 2 × 2 grid of figures (one column at phone width), each read aloud by its
  alt text.

## M6FA.5 `marks` on `graph-artifacts`

`graph-artifacts` gains `marks: shown | hidden` (default `shown`, so every file today reads the
same). `hidden` draws every k-mer and edge plain, for an option or a stem that must not give the
answer away; a `pick` figure is drawn hidden while asked, whatever `marks` says, and with its marks
once answered. *My call*, from the boards.

## M6FA.6 The composer's Interaction step (S4)

Between Data and Describe, **only for a kit with tasks**; the step list is the kit's. *What the
learner does*: *Nothing* or each task, its fields as a form from the task's schema (as Data's).
*Computed*: the right answer, the wrong one, and how it is drawn while asked, named, never typed.
**Every state** strip under the preview: start, midway (`trace`: the first half of `accept[0]`;
`pick`: `accept[0]` chosen, unchecked), wrong, answered, each drawn by the page's component.

**Checks**: the task's findings (CS1028–CS1032, with the server's codes, as the kits' are twinned);
*One right answer* (it says how many selections `accept` holds); *A wrong answer exists* (it names
`wrong`; it cannot fail for these two tasks); **Every state draws**: each state rendered in the
browser without an error (an error boundary per state). The last is a browser check, as the preview
is: the server refuses only the task's findings. Save waits for every check, as in M6.5.

*Nothing* removes `interact` from the file; the edit goes through the M6.5 document ops, so the rest
of the file is kept as written.

## Decisions, and the alternatives rejected

- **The task in the figure file** (M6FA.1), not on the question. *Operator, 2026-11-06.*
- **A selection is a list of k-mers, right iff one of `accept`** (M6FA.3). Rejected: a grader per
  task (two code paths to keep twinned), and a score between 0 and 1 for a partly traced path (a path
  is right or not; a partial one is the midway state, not an answer).
- **`accept` filled when the folder is read** (M6FA.3), so grading keeps one signature. Rejected:
  `accept` passed in by each caller.
- **Moves only along arrows** (M6FA.4): a wrong path is possible, a broken one is not. Rejected: free
  clicking with a "not connected" refusal at Check, which tells the learner less, later.
- **Real buttons over the drawing**, not `role="button"` on SVG groups: Tab and the 44 px target come
  for free.
- **Figure options here, not in M6.7** (operator, 2026-11-06): they need no seeds, and M6.7 stays
  about problems.
- **`marks` as a kit setting** (M6FA.5), not a rule that every figure in a question is drawn plain:
  `green-path` asks *follow the green path*, and needs its highlight.
