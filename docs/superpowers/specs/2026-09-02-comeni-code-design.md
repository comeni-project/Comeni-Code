# Comeni Code — design

**Status: design, not agreed implementation.** Written 2026-09-02 from a brainstorming session.
Nothing here has been built. The implementation plan does not exist yet.

Comeni Code is the third repository under the `comeni-project` umbrella, beside
[Comeni Labs](https://github.com/comeni-project/Comeni-Labs) (Mendel, Wiener) and
[comeni-registry](https://github.com/comeni-project/comeni-registry). It is the learning
platform. Labs' `CLAUDE.md` has carried the line *"Comeni-Code is a separate repo: the learning
platform. Do not build it here"* since the beginning; this is the first document that says what
it is.

---

## 1. The claim

> **You learn the thing you are about to run, and every sentence says where it came from.**

That is deliberately the same shape as Mendel's claim (*same goal in → same pipeline out, and
nothing was guessed silently*), and for the same reason: the honesty half is the part that is
hard, and stating it is what makes it checkable.

**What it does not claim.** Determinism. Prose is generated by a model and a model is not a
resolver; the same prompt does not produce the same paragraph. Code promises **provenance**,
not reproducibility: every claim traces to a citation, every node records who drafted it and who
approved it, and the learner can see both. Do not let this drift into a determinism claim by
analogy with Labs — §5.6 is the boundary.

---

## 2. Why this is worth building, and what killed the last two attempts

This section exists because the idea has been built before, twice, by capable people, and both
attempts are gone. Anything that ignores that is a third attempt.

**Metacademy** — "a package manager for knowledge": 487 concepts, 1,208 prerequisite pairs,
each node carrying a description, learning goals, time estimates and resource pointers, with a
learning plan generated by walking the graph backwards from a target concept. Built by Roger
Grosse and Colorado Reed. The GitHub repository is **archived**, last pushed 2023-05-01;
`metacademy.org` refuses connections as of 2026-09-02. It survives as a dataset that
prerequisite-relation researchers cite.

**Khan Academy's Knowledge Map** — the dependency constellation of ~400 skills, removed around
2013–2016 in favour of Missions and then Course Mastery. Part of the reason was incidental (it
was built on the Google Maps API), but it was replaced by a linear structure and never rebuilt,
despite a decade of user requests. In August 2023 Sal Khan said the concept map would return "in
about a year, using generative AI". It has not.

**What is alive splits cleanly by what the graph is *for*:**

| Alive | Role of the graph |
|---|---|
| Math Academy — several thousand topics, tens of thousands of prerequisite edges | **Backend.** Learners see a daily task list. The graph drives *scheduling*: "fractional implicit repetition" — reviewing a topic implicitly reviews its prerequisites. |
| roadmap.sh — 500K+ active learners | **The whole UI, holding no content.** A map of what to learn that links out. Cheap to maintain, honest about what it is. |
| Rosalind — 284 problems, ~135K users, running since 2012 | Light scaffolding over auto-graded problems. Assumes you already know what an aligner *is*. |
| Healthy Gamer's Dr. K's Guide | A hand-curated hex grid of **5** modules, FFX sphere-grid styling, a "Core Knowledge Path" unlocking each module. Small, single-author voice. |

**The pattern: graphs that schedule succeed; graphs that decorate succeed cheaply; graphs that
*are* the product die.** Metacademy and the Knowledge Map both put the graph on the front door
and asked it to carry the content.

### 2.0.1 What that pattern does *not* license — corrected 2026-09-02

The first draft of this section concluded *the front door is a path, and the map is a reference
view*. That was the wrong lesson, and the operator caught it: a legible network map is the whole
reason this product is interesting, and designing it away answered a research finding that was
never about maps.

**What killed Metacademy and the Knowledge Map was an undifferentiated DAG** — no regions, no
landmarks, no route — presented to a newcomer as the first thing they see. The games that make
enormous networks work do not hide them; they make them **readable**:

- **Path of Exile** — 1,325 nodes, and its own designers describe the tree as *a map with
  suburbs and roads*: clusters of related passives are suburbs, the connecting runs are roads.
  **Notables** carry larger icons and names so a whole cluster can be understood at a glance
  when zoomed out, and search highlights matching nodes with a pulsing glow across the entire
  tree.
- **Final Fantasy X's sphere grid** — a roughly circular grid of interconnected nodes arranged
  in *smaller circular clusters*, which is the shape Healthy Gamer's Dr. K's Guide borrows
  outright for its hex grid (its own product manager names the sphere grid as the inspiration).
- **Healthy Gamer** bounds it differently again: five modules, hand-curated, each unlocked by a
  Core Knowledge Path.

**Binding consequence:** the network *is* the picture. Regions are drawn and named; **threshold
nodes are the landmarks** that make a region readable from far away — they are this product's
Notables, which is a second, independent argument for §6.3's rare boolean; and the **spine is
drawn as a route through the network**, not as a replacement for it.

### 2.0.2 The map is a transit map — settled 2026-09-02

A first attempt at §2.0.1 drew a constellation: glowing coloured points, tinted region blobs,
diamonds for thresholds. The operator's verdict was **cartoonish**, and that is the correct
reading of it — it was a game map, where Labs' whole visual argument is that a screen is an
*instrument*. Three specific failures, worth recording because they are easy to repeat:

1. **It broke Labs' own colour law.** `tokens.css` states it plainly: *settled gets NO COLOUR AT
   ALL. Only measured (amber) and open (red) spend any.* Every known node was painted teal.
2. **Glow is chartjunk.** Tufte's term for content-free embellishment, and box-shadow halos on
   nodes are the definition of it: they encode nothing.
3. **Blobs and diamonds are decoration standing in for structure.** A tinted ellipse says
   "region" without saying where the region ends.

**The form settled on is MetroSets** — a published hypergraph visualisation method that draws
hyperedges as coloured lines running through their member nodes on a schematic transit map. It
is the right answer for reasons beyond taste:

- **A track is a line, a node is a stop, and a node several tracks need is an interchange.**
  The reusable-node claim — the thing this whole product rests on — stops being a paragraph and
  becomes something a learner sees in one glance.
- **A transit map is drawn like an instrument**: octilinear segments, hairlines, restrained
  colour, no glow. Schematic rather than geographic, which is exactly the trade a prerequisite
  map wants — relative order and connection matter, absolute position does not.
- **Zones replace blobs.** Regions become bands with labelled boundaries, which say where a
  region *ends*.

**The trunk is straight, and this is not a stylistic preference.** The first transit draft ran
the main line octilinearly — up, across, up again — and the operator's reading was that the core
was *not aligned, so it looks confusing*, which is correct: a route that zigzags makes the reader
work to find the very thing the route exists to make obvious. Real transit maps straighten the
trunk and bend the branches, for exactly this reason.

So: **the spine is one straight line with evenly spaced stops**, labels alternating above and
below so adjacent labels never crowd. **Everything else branches off it at a named stop**, which
makes a divergence legible *as* a divergence — you can see that *Call variants* leaves after
*what an aligner does*, and that *Assemble a genome* leaves after *FASTQ on disk*. Elaborations
hang off their own stop as short stubs.

Zoom then changes labelling density rather than dimming: your line → where the branches leave →
every stop including elaborations and the minor ones nobody names. That is honest in a way
dimming is not, and it is how a real transit map already works.

**The warning that governs all of this** comes from Obsidian's graph view, which its own
community describes as *"beautiful and almost completely useless"* and *"more fun to look at
than navigate"*. Past a few thousand nodes it is a hairball; what rescues it is filtering,
depth-limiting and grouping. Two consequences: **filtering is not a feature, it is the
precondition**, and the map's second honest job is an authoring **health check** — finding
orphan nodes and unexpectedly disconnected clusters — which belongs in subsystem A, not B.

**And do not bundle edges.** Edge bundling reduces clutter but introduces ambiguity: following
a bundled edge from source to target can suggest connectivity that is not there. In a
prerequisite map, following an edge *is* the task.

### 2.1 What is different here

1. **The prerequisites are real.** In most subjects people try this on, dependencies are
   conventional. You cannot understand a splice-aware aligner without introns. The graph is
   load-bearing rather than decorative.
2. **There is no incumbent.** Searching for a bioinformatics concept-prerequisite learning
   platform returns biomedical research knowledge graphs and nothing educational.
3. **There is an external forcing function, and it is the whole strategy.** Metacademy was a
   beautiful graph with no reason to visit it on a particular Tuesday. Code's learner has a
   pipeline to run and a decision they do not understand. That is subsystem C, and it is the
   part no competitor can copy.

### 2.2 The tension that must be stated

**Labs automates the thing Code teaches.** MIT's 2026 Ad Hoc Committee report on AI use in
teaching names this failure mode as **"cognitive surrender"** — learners disengaging from
productive struggle because a machine will do it. If Mendel builds the pipeline, the honest
question is why anybody should learn what STAR does.

The answer, and it is a *design constraint* rather than a reassurance: Mendel does not emit an
oracle. It emits a decision with a tier, a premise, a citation and a reason. That makes a
pipeline a **worked example**, which is MIT's principle 7 — *augmentation, not automation*.
**Code must point at Labs' reasoning, never at its output.** A node that says "Mendel picked
STAR" has failed; a node that says "Mendel picked STAR because `star/align.reads` declares
`state_required_conventional: [trimmed]`, and here is why that rule exists" has not.

## 3. Vocabulary

Chosen partly to avoid collisions with Labs, which is a working codebase with its own meanings.

| Term | Means | Why not the obvious word |
|---|---|---|
| **node** | One idea, with a claim, prerequisites and evidence | **Never "module".** In Labs a module is an nf-core process on disk (`registry/tools/nf-core/star/module/`). Reusing the word guarantees permanent ambiguity. |
| **track** | An ordered route through the graph to an outcome | "Course" implies linear, enrolled and completable — the opposite of a graph entered from the middle. |
| **claim** | The one thing a learner can do after a node | The instructional-design term is "learning objective"; `claim` matches Labs' register (contracts, premises, citations). |
| **spine** | The shortest complete path through a track | Labs already uses this word for exactly this idea: *"the RNA-seq spine, ~15–20 modules on the canonical path, not the full decision tree."* One word, both halves of the system. |
| **elaboration** | A node hanging off the spine, reachable but not in the way | Reigeluth's own term (§6.2). |
| **threshold** | A portal concept: transformative, integrative, irreversible, troublesome | Meyer & Land's term. Not "priority" — see §6.3 on why a scale inflates and a boolean does not. |

## 4. The v1 learner

**A wet-lab biologist who has been handed sequencing data.** Decided 2026-09-02 by the operator,
over two alternatives (a bioinformatics student/new hire; a Labs user mid-task).

Consequences, stated because they were the argument against this choice:

- **The graph must go all the way down to DNA.** The content bill is roughly triple that of the
  student option.
- **Very little can be assumed.** No command line, no Python, no genomics vocabulary.
- **The spine is what makes this survivable** (§6.2). Depth becomes something a learner descends
  into when a node does not land, rather than a wall they face on day one. A track's spine can
  be 11 nodes over a graph 60 deep.
- **This is the largest market and the strongest "nobody serves this" case.** Reviews of the
  bioinformatics training landscape (EMBL-EBI's FAIR training portal, the Galaxy Training
  Network, Bioconductor's training committee) agree that basic computational skills are rarely
  taught in life-science degrees, producing researchers tasked with analysing data they cannot
  analyse.

## 5. The node

### 5.1 Typed holes

A node is not drafted as one blob. It is a set of **typed holes**, each drafted and approved
separately — the `mendel-forge` pattern (`HoleFiller`, `NoFiller` declining by default,
`forge verify`, `forge land`). The reason is in §5.5: a single Approve button over finished prose
is the specific interaction the evidence says fails.

| Hole | Drafted by | Why it is its own hole |
|---|---|---|
| **claim** | human, or AI-proposed and human-rewritten | One sentence: what you can do after. Everything else is checked against it, so it **gates** — approving the rest before the claim is settled is wasted work. |
| **prerequisites** | AI proposes, human confirms **each edge** | This *is* the graph. Each edge carries its own reason ("you cannot parse a CIGAR string without knowing what an alignment is"), reviewable one at a time. |
| **exposition** | AI, grounded in cited sources | The bulk, and where hallucination lives. Subject to the citation constraint (§5.3). |
| **worked example** | AI, mechanically verified where possible | Can be *real*: a command, a file, five lines of FASTQ. Executable, therefore checkable. |
| **check** | AI drafts, human validates | A 90-second question that returns on a spacing schedule. Feeds the review queue (§9.1) and item discrimination (§5.3). |
| **problem** | AI drafts, human validates, **machine grades** | Rosalind-shaped: a generated dataset, one auto-graded answer. §5.1.1. |
| **misconception** | AI, from literature and forums | The wrong model learners actually hold. Highest pedagogical value per word; the hole that makes a node read as if written by someone who has taught. |
| **framing** | AI, cheap, regenerable, **one per track** | The escape from the reusability paradox (§5.2). The only hole with N versions. |
| **threshold** | node author, boolean | §6.3. |

Two consequences fall out. The claim/prerequisite pair is the **only** part that must exist for
the graph to be navigable — exposition can be a stub and the map still works, which makes a
skeleton-first authoring strategy possible. And `worked example` is checkable in a way the
others are not.

### 5.1.1 `problem` is not `check`, and conflating them was an omission

Added 2026-09-02, after the operator asked where the Rosalind-style questions had gone. The
first draft had one assessment hole holding a multiple-choice question, which throws away the
mechanism that has kept Rosalind alive since 2012 and Project Euler since 2001.

| | `check` | `problem` |
|---|---|---|
| Shape | a question with options | statement, **Given / Return**, sample dataset, sample output, then *your own generated dataset* |
| Graded by | matching an answer key | comparing one submitted answer against the one computed for your dataset |
| Costs | seconds | minutes to hours |
| Returns | yes — on a spacing schedule | no; solved once, and never expires |
| Means | you can still recall this | **the node is solid** |

The distinction is load-bearing in three places. **Only `problem` marks a node solid** — reading
does not, and answering a multiple-choice question does not. **Only `check` feeds the review
queue**, because a spaced-repetition schedule needs an item you can answer in seconds.
And **a per-learner generated dataset makes an answer worthless to anyone else**, which is how
Rosalind runs an auto-graded platform of 284 problems without an honour code. Project Euler adds
the other half of the argument: a numeric answer needs no code execution on our side, so the
grader stays trivial while the problem can be arbitrarily hard.

**Rungs.** The v1 learner (§4) did not sign up to program, so `problem` carries a rung:

1. **Read it off the file** — a text editor is enough.
2. **One command** — the shell, given to them.
3. **A few lines they write.**
4. **It has to be efficient** — 50M reads, not 50k.

Rung 1 exists so that *"I cannot program"* never becomes the reason a wet-lab biologist stops.

**Wrong answers are answered from the `misconception` hole**, not by a model reading the
submission. That keeps the feedback deterministic, reviewable and attributable — and it gives
the misconception hole a second consumer, which is what stops it being decorative.

### 5.2 The reusability paradox, and why `framing` exists

David Wiley's reusability paradox: a learning object's internal context is *directly* correlated
with its educational efficacy and *inversely* correlated with the number of aggregations it fits
into. Generic is reusable and does not teach; contextual teaches and does not travel. Wiley's
sharpest point is that designers who try to strike a balance produce material that is **neither**
effective nor reusable — which is the historical fate of the learning-object movement, and the
Carpentries reached the same conclusion for this exact audience.

A single canonical DNA node reused across every track walks straight into this.

**The escape is economic rather than clever.** The reason context and reuse trade off is that
contextualising costs an author-hour per context, so nobody does it and everything ends up
generic. If per-track framing is *cheap to generate and cheap to review*, a canonical node can
have a genuinely different way in for the RNA-seq track and the variant-calling track. Context
**and** reuse, because the expensive half stopped being expensive.

This is the strongest argument for the AI authoring pipeline, stronger than volume.

### 5.3 Ground truth

`forge verify` can be a five-rung ladder because `meta.yml` and `main.nf` are on disk: a contract
either agrees with its module or `MD0104` refuses it. **A lesson has no `meta.yml`.** A
confidently wrong, fluent, well-cited paragraph passes every mechanical check that can be
written. Copying the forge's ceremony without replacing its ground truth produces the queue, the
codes and the approval ritual with the rung that made it trustworthy missing.

Three replacements, needed at different stages:

1. **Citation grounding — from day one.** A node may only assert what it cites; the model
   composes *from* retrieved cited material rather than from its weights. Not merely a purity
   argument: expert ratings for conceptual support and instructional quality are higher for
   pedagogical-RAG conditions than prompt-only ones, and Labs measured the same effect from the
   other direction — grounding a local model in exact registry retrieval took the forge from
   69% to 88%, and two of the three fixes behind that were *the question never said what it was
   about* and *the evidence was not readable*.
2. **Partial mechanical ground truth, in three places — and it is free.**
   - **Tool nodes.** A node about STAR *does* have a `meta.yml`, a contract, ports, declared
     types, `ext_args`, a container and a citation. A claim that disagrees with the contract can
     be refused mechanically, exactly like `MD0104`.
   - **Worked examples.** They execute or they do not.
   - **Citations resolve.** A DOI either resolves or it does not. MIT's report flags
     hallucination of *facts and citations* specifically; this rung is cheap and catches it.
3. **The learner, eventually.** Once people answer checks, a node everyone passes without
   reading is broken, and a node whose checks everyone fails is broken differently. That is item
   discrimination, and it is what Math Academy and ALEKS actually run on. A v2 mechanism — it
   needs traffic — but the schema must have room for it from the start (§8.3).

Note the ordering this implies: **the nodes that verify are the ones nearest Labs.** That is an
argument for building outward from the tools even though the v1 learner needs the graph to reach
down to DNA.

### 5.4 Prompts are declared data; the node body is the artifact

Prompts live as versioned files in git, referenced by stable code — diffable, reviewable,
citable. This is Labs' `diagnostics.yml` pattern and the conclusion of its declared-data
argument (issue #43: every comparable catalogue keeps human-curated data as files in git,
because a database has no diff, blame, review, signature or merge).

**But pinning the prompt does not pin the output.** Prompt + model + sampling → text, and none of
it is reproducible the way `Goal → .nf` is. So:

- The **artifact** is the approved node body.
- The prompt id, model id, and retrieved sources are recorded as its **provenance**.
- A regenerated node **must replay every human edit** made to the previous version, or a
  reviewer's work evaporates at the next model upgrade. This is `pipeline.yml`'s rule that
  decisions are replayed from the record rather than re-asked.
- **A model's edit is recorded separately from a person's.** Labs already has `model_override`
  and `model_override_by` beside `human_override`; the distinction matters more for prose than
  it did for parameters.

### 5.5 The review interaction is the highest-risk design in the project

This is the part expected to fail, and there is direct evidence for how.

In a controlled comparison of assessment items, **teacher-revised AI items carried significantly
more flaws than teacher-only items** — not fewer. The teacher-AI condition showed a *marked
increase* in flaws consistent with automation bias, evidenced by measurably lower interaction
density: reviewers accepted drafts with minimal critical engagement. Separately, blind experts
preferred LLM-generated items 60% of the time and rated ChatGPT questions 4.00 against 2.71 for
human ones — while human-authored questions had significantly **higher discrimination indices**.
AI items looked better and worked worse.

The evidence is not uniformly negative: GPT-generated exams *under teacher supervision*
outperformed both teacher-written and unsupervised-AI ones. The reconciliation offered by the
literature is blunt and useful: **the human–AI interaction workflow, not model capability, is the
quality determinant.**

So the question is not "should AI draft nodes" (yes) but **what the review screen forces the
reviewer to do.** A screen showing polished prose with Approve/Reject will be rubber-stamped;
that outcome is measured, not speculated. Mechanisms that force engagement, to be designed and
tested against each other:

- Hide the draft until the reviewer has written the node's claim themselves.
- Show the draft beside its cited sources, with uncited assertions highlighted.
- Require the reviewer to answer the node's own checks before approving them.
- Present two drafts and require a choice plus a reason.

Relevant precedent from inside the project: Labs' forge was found unusable by **walking the loop
as a user**, not by reading the code, and is currently deprecated pending that rework. Copy the
forge's philosophy; do not copy its interface.

### 5.6 Disclosure

Every node discloses to the learner: AI-drafted or human-drafted, human-approved, by whom, when.

MIT's report recommends that instructors using AI for content or feedback disclose it, and
records that students perceive undisclosed instructor AI use while facing AI restrictions as a
**double standard**. It also states that AI must never be listed as an author. This is
"nothing was guessed silently" in the register Code speaks, and it is a differentiator rather
than a liability.

## 6. The track

### 6.1 A track is an authored artifact, not a query

Tracks have their own typed holes and their own approval moment. The track author decides which
nodes are on the spine; the node author decides whether a node is a threshold. **Two authorities,
two review moments.**

| Track hole | Notes |
|---|---|
| **outcome** | What the learner can do at the end. Concrete and real — "align your reads and get a counts matrix", not "understand RNA-seq". |
| **spine** | The ordered shortest complete path (§6.2). |
| **elaborations** | Nodes reachable from spine nodes, off the main path. |
| **framing** | Per-node, per-track (§5.2). |

### 6.2 `spine` — sequencing, not prioritisation

Reigeluth's elaboration theory and its Simplifying Conditions Method: find the **simplest version
of the whole task that is still representative of the whole task** — the *epitome* — teach that,
then elaborate outward, "zoom lens" style.

A learner should not meet 100 nodes and be asked to pick the important ones. They should get a
**complete, honest, short path to a real outcome**, with the other 90 reachable and out of the
way. A track therefore advertises a small honest number: *"11 nodes to your first alignment."*

`spine` is a property of the **track**, not the node: a node that is spine in the wet-lab track is
an elaboration in the developer track. Same shape as `framing`, which is a sign the model is
coherent.

**Relief from an unexpected direction:** research on concept maps finds that interconnections act
as *structuring* elements that **decrease** extraneous cognitive load — adding structure does not
overload learners. A hundred nodes are not frightening because there are a hundred; they are
frightening when **flat and undifferentiated**. Structure is the cure, not the disease. What
kills is the flat list and the front-door graph — which is what Metacademy and the Knowledge Map
put on their home pages.

### 6.3 `threshold` — a rare boolean, never a scale

A threshold concept (Meyer & Land) is a **portal**: transformative, integrative, irreversible,
bounded and *troublesome*. Once through, a whole region of the subject becomes thinkable. This is
applied work in biology education, not a metaphor — *CBE—Life Sciences Education* treats
biological variation as a threshold concept and attempts to measure threshold crossing.

Plausible portals here: the DNA→protein relationship; coordinate systems and off-by-one
conventions; *a read is a sample of a molecule, not the molecule*; multiple testing.

**Why a boolean and not a 1–5 priority.** A scale inflates — every author marks their node a 4.
A boolean with a published bar (must be transformative **and** integrative **and** irreversible
**and** troublesome) resists inflation and is falsifiable in review. Expect 5–8 in a 100-node
graph. Threshold nodes get the `misconception` hole filled properly, the hardest checks, and
visual weight.

### 6.3.1 Prerequisites are a hypergraph, not a graph — open, and worth deciding early

The `prerequisites` hole (§5.1) is currently a set of edges: *D needs A*, *D needs B*, *D needs
C*. That representation **cannot distinguish two different claims**:

- *You need A **and** B **and** C before D.* — one conjunctive requirement.
- *You need A, **or** B, **or** C — any of them gets you in.* — three alternative routes.

Three separate edges look identical in both cases. The correct model is a **hyperedge**: one
requirement joining several nodes at once. This is not novel in the field — prerequisite
structure research works with *conjunctive* skill models explicitly — and it matters here in
three concrete places:

- **`readiness` (§6.4) is computed wrongly without it.** A node whose prerequisites are
  alternatives becomes reachable much earlier than a plain DAG says.
- **The review scheduler is wrong without it.** Math Academy's fractional implicit repetition
  credits a topic's prerequisites when the topic is reviewed. Crediting all three members of an
  *or* is crediting things the learner may never have touched.
- **It changes the review interaction.** A reviewer confirming *"these four together are what
  you need"* is answering a different, better question than confirming four edges one at a time.

**The drawing consequence is real but manageable.** Hypergraph visualisation splits into a
*subset standard* (hyperedges as closed envelopes around their members — Euler diagrams, Bubble
Sets) and an *edge standard* (clique expansion, or an explicit crux node). Both become illegible
as the hypergraph grows, and this is where MetroSets earns its place twice over: a line through
its member stops **is** a readable hyperedge, and it is the one form in the literature that
scales.

**Not decided.** The cost is a more complex schema and a harder editor, and a v1 whose graph is
almost entirely conjunctive would pay it for very little. What is decided is that the schema
must not *foreclose* it: a prerequisite is a **group** with one member by default, never a bare
edge. That is a cheap shape today and an impossible retrofit later.

### 6.4 `readiness` — computed, never authored

The **fringe**, in the sense of knowledge space theory: the set of nodes a learner is ready to
learn, given the graph and what they know. ALEKS places a learner in 20–25 questions using this
machinery. Zero authoring cost — it falls out of the graph plus the knowledge state.

**Capped at 2–4 options on screen.** Iyengar & Lepper: a table of 6 jams produced a 30% purchase
rate, a table of 24 produced 3%. Optimal choice sets land at two to four.

## 7. Subsystems

Four, each with its own spec → plan → implementation cycle.

- **A — content model and authoring pipeline.** Node and track schemas, typed holes,
  prompts-as-declared-data, the approval loop, the review interface, the verification rungs.
  Labs-lineage work. Needs no learners to build or test.
- **B — learner-facing platform.** Path rendering, node reading, checks, knowledge state, the
  review scheduler, the map view. Needs A to have output.
- **C — Labs integration.** Enter a node from a pipeline decision; run the pipeline from inside a
  track. What makes this not-Metacademy.
- **D — social and game layer.** Refused for now; see §9.

### 7.1 A: the authoring loop

`draft → fill (hole by hole) → verify → approve → land`, deliberately echoing
`forge draft → fill → verify → land`. Landing writes a node into the content layer; nothing is
written automatically, which is Labs' invariant 2 (*AI authors artifacts offline; humans approve;
runtime is pure lookup*) transplanted intact.

### 7.2 B: the interface rules that follow from §2

- **The map is the front door, and it is a transit map** (§2.0.2): a track is a **line**, a node
  is a **stop**, a node several tracks need is an **interchange**.
- **The trunk is straight; branches bend.** The track's own line runs dead straight with evenly
  spaced stops and labels alternating above and below. Every other segment is octilinear — 0, 45
  or 90 degrees. Relative order and connection are the content; absolute position is not.
- **A branch leaves at a named stop**, so a divergence reads as one.
- **Zones, not blobs.** Regions are bands with labelled boundaries, so a region has an end.
- **Threshold nodes are interchanges** — drawn larger and always labelled, legible when zoomed
  out. PoE's Notables, and the reason §6.3's boolean stays rare: a map where everything is a
  landmark has none.
- **Settled spends no colour.** Labs' law, not a preference. Only stale (amber) and next (blue)
  spend any, plus one colour for the line you are on.
- **No glow, no gradients on marks, no bundled edges** (§2.0.2).
- **A zoom control, three positions, changing labelling density rather than dimming:**
  *your line* → *+ the lines that share your stops* → *every minor stop*.
- **Search highlights across the whole map**, PoE-style — the affordance that makes a large
  network navigable without shrinking it, and the filtering that Obsidian's hairball says is a
  precondition rather than a nicety.
- **Elaborations are also side-doors on the node being read**, for the learner who never opens
  the map.
- **Labels are outcomes and time, never jargon or counts alone.**

### 7.3 C: the two directions

- **Labs → Code.** A decision in `pipeline.yml` links to the node explaining it. Mendel already
  records a tier, a rule, a premise and a citation for every value; that is the anchor.
- **Code → Labs.** A track ends by running the real pipeline. The learner's outcome is an
  artifact, not a certificate.

Per §2.2, C points at Labs' **reasoning**, not its output.

## 8. What v1 is

**A + B + C. One vertical slice. No D.**

### 8.1 The slice

**One tool, all the way down.** STAR → alignment → sequencing → DNA, plus the algorithmic branch,
with a wet-lab-biologist track whose spine is ~11 nodes over a graph of perhaps 40–60. It ends
with the learner running a real pipeline.

Chosen because it exercises every hole, both edge kinds, all three verification rungs and the
Labs link — and because if the authoring loop cannot produce *this*, it cannot produce 500 nodes
either.

### 8.2 The real constraint is content, not software

The software is a prototype in a week and something good in a month. **The writing is the
product.** Chapman Alliance benchmarks put the simplest e-learning (text, basic narration, simple
quizzes) at ~34 development hours per finished hour of instruction; 79 on average; ~184 for
moderately interactive. At 15 minutes a node that is roughly 8–20 hours each before AI drafting.

**The first thing to find out is whether the authoring loop produces nodes a human learns from.**
Everything else is downstream of that answer.

### 8.3 Record the events from day one

Item responses with timestamps, node views, review intervals, mastery estimates. The review
scheduler in B needs them anyway for pedagogical reasons, and knowledge state is unrecoverable if
it is not logged from the start. This also keeps D a rendering decision rather than a schema
migration (§9).

## 9. D is refused, and this is the argument

Not "not a priority" — the evidence says the standard mechanics are more likely to harm this
audience than help it.

The meta-analyses look positive on their face (g ≈ 0.46 to 0.82, with points+badges+leaderboards
combinations among the higher values). **The moderators are the story:** effects are largest for
**young children in elementary education**, and **higher-achieving students benefit more than
lower-achieving ones** — which inverts the goal, since the person who most needs this platform is
the one who is struggling. Nearly all of that literature studies compulsory, short-duration,
classroom contexts. Code's context is adult professionals, self-selected, unsupervised, over
months.

Three findings that bear on that context:

- **Hanus & Fox (2015)** ran the clean experiment: same 16-week course, two sections, one with a
  leaderboard and badges. The gamified section showed *less* motivation, satisfaction and
  empowerment over time, and **scored lower on the final exam**.
- **Deci, Koestner & Ryan's meta-analysis of 128 studies**: tangible, expected,
  engagement-contingent, completion-contingent and performance-contingent rewards all
  significantly undermined free-choice intrinsic motivation. The overjustification effect fires
  hardest on people who were **already motivated** — which describes someone learning what STAR
  does because they have a dataset to align.
- **Novelty decay is measured in weeks.** A new mechanic lifts engagement ~3 weeks, then returns
  to baseline; participation drops by month three or four. Duolingo's intermediate plateau is the
  same curve, defended by behavioural scientists and a hundred million users.

**Leaderboards** motivate the top 5–10% and trigger avoidance in everyone else.

**Per-lab competition is the worst variant and should not be built.** Labs are hierarchical
workplaces. A leaderboard visible across a lab becomes a performance metric the moment a PI can
see it, shifting the incentive from *learn this* to *be seen to have learned this*; it lands
hardest on the people with least power, and "how much of the platform have you completed" is a
poor proxy for competence that a supervisor may nonetheless treat as one.

### 9.1 What replaces it

**A number may be a measurement. A number may not be a prize.** Showing someone their knowledge
state is *information* and feeds the competence need that drives intrinsic motivation; giving
someone 50 XP for showing up is a *reward* and substitutes for the reason they came. These look
identical in a UI and are opposite in effect. Math Academy is the reference implementation: XP
denominated in topics actually mastered — a unit of learning, not a prize for attendance.

1. **The knowledge state, rendered.** What you know, what you are ready for, what has gone stale.
2. **A spaced-repetition review queue.** The honest version of the streak: *come back tomorrow*
   justified by the spacing effect rather than loss aversion. This is the one mechanic that
   genuinely **requires** the graph — Math Academy's fractional implicit repetition computes the
   schedule over the DAG, because reviewing a topic implicitly reviews its prerequisites. The
   graph earning its cost.
3. **C is the retention mechanic.** The user returns because they have a pipeline to run. Real,
   external, immune to novelty decay, and unavailable to any competitor. Streaks are what you
   build when you do not have that.

### 9.2 If D is ever built

Binding constraints, in the spirit of Labs' invariants:

1. Every number displayed is a measurement of learning, never a payment for activity.
2. **Nothing expires.** Streaks work by threatening loss; that is the mechanic that produces
   minimum-viable-lesson grinding.
3. Never rank a person against another person.
4. Any mechanic is evaluated at **week 12**, not week 1 — the novelty window makes anything look
   good.
5. Reward accuracy and spacing, never volume.

Reopening condition: evidence from real learners that C alone does not explain return visits.

## 10. Open questions

1. **Which review interaction actually defeats automation bias?** §5.5 lists four candidates;
   none is chosen. This wants an A/B test against a measurable outcome (flaw rate in approved
   items), not an opinion.
2. **Images and figures.** A figure is an assertion with a source and a licence. CC-BY
   compatibility matters here the way it does for `comeni-registry`. Unresolved: generate,
   commission, or cite-and-embed.
3. **The check grader.** Rosalind-style auto-grading works for objective problems; MIT's report
   argues for human-delivered feedback over purely automated grading. Where is the line for a
   platform with no instructors?
4. **How deep does "all the way down to DNA" actually go** for the wet-lab track before the spine
   stops being honest?
5. **Content licence.** Labs is Apache-2.0 and registry data is CC-BY-4.0. Node prose is closer
   to registry data than to code.
6. **Where the content lives** — in this repo as files (the declared-data argument), or in a
   database. §5.4 leans files; not decided.
