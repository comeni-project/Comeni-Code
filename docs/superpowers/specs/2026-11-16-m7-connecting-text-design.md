# M7.4 — Connecting text

The deterministic weaver remains the source of every route. A connecting-text bundle snapshots
its goals, known nodes, ordered stops and claims. A digest identifies the exact input. The three
text kinds are introduction, adjacent-stop bridge and why-for-goal. Node bodies never change.
At most 40 stops enter one bounded generation job; longer routes still work without optional
connecting text. One closed-schema reply must name the exact expected text keys. No URL or
arbitrary tool enters the model context. Failure leaves text absent and the route usable.

A learner's route page asks explicitly through a bounded endpoint for the bundle, starting at
most one background job per snapshot. Reading route JSON never calls a model. Generated text is
plain text, marked not yet reviewed. Each item stores its allowed claims beside its text. The
model is instructed to use only that item's claims and goal; automatic structure/length/reference
checks do not prove semantic truth. S9's human review remains required for publication.

The gateway stores call metadata without prompts/replies or learner identity. Site and intake
limits bound calls. Snapshot comparison prevents old connecting text from being silently reused
after adjacency, claim or goal changes. A changed graph flags the old bundle for re-review; a
fresh bundle receives fresh text and no inherited approvals.

This part builds persistence, jobs and learner display. M7.5 owns reviewer decisions, rewrites,
version conflicts, named tracks, publication and catalogue.
