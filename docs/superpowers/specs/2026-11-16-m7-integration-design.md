# M7 — Integration and acceptance

Complete the cross-part seams before calling the phase implemented. Requests gain advisory
duplicate/covered-node suggestions through the declared grouping site, request-to-request merge,
type/region/waiting/demand filters, saved views and keyboard decisions. Model suggestions never
change request state; only an explicit version-checked human decision merges or accepts.
Merging requests moves their submission receipts/demand to the surviving request and logs the
target. Later receipts follow the surviving disposition. Missing or terminal merge targets are
refused; lock order prevents opposite-direction merges from deadlocking or creating cycles.

Route impact counts distinct submitted missing-goal route attempts, not invented model scores.
Intake accepts a bounded route context only when it includes the named missing indexed ID.
Mixed existing/missing goals show the available route and explicit not-written stops with request
links. Missing nodes never enter the deterministic graph as fake facts. S8 prioritises actual
route demand and preserves draft-derived stages.

The remaining M7 model sites become configurable when their screens/workers are wired. Operator
caps remain authoritative. Skeleton scores show their rubric parts and reasons; source mapping
and request evidence remain inspectable across the handoff.

Final acceptance includes focused integration cases, full Python/web suites, lint/types/build,
migration consistency, CI and local browser walks in both themes. Real GitHub landing stays
deferred by operator order; model transport can be stubbed for repeatable local walks, with real
model behavior reported separately. No fixture is published as real content.
