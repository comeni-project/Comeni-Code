# M5.2 — Drafting with provenance: implementation plan

**Status: written after the operator approved the design, 2026-11-15. Implementation pending.**
Parent: #447, under M5 (#445). Spec: `docs/superpowers/specs/2026-11-15-m5-drafting-design.md`
(M5D.1–M5D.7). Boards: `.design/_m5_drafting.mjs`, built by `.design/build_pages.mjs`.

**Goal:** an author can request, compare and keep a block redraft, resource suggestion or figure
change. Earlier human corrections survive; overlaps require a decision. Every saved AI-origin
item keeps its source/model/prompt history through review, landing, indexing and later editing.

**Architecture:** pure public provenance in `code-schema`; proposal orchestration in
`code_api.studio.ai_drafting`; pure replay in `studio/ai_replay.py`; typed edit adapters shared
with the existing content API; the existing gateway makes every call; Celery runs one claimed
proposal outside draft locks. React uses the existing query hooks and draft mutation executor.

## Contracts pinned before wiring screens

**Public format:** `provenance.json`, version 1, with closed fields. `receipts` are keyed by a
public receipt UUID; `items` bind existing content-item keys/fingerprints to receipt UUIDs.
A receipt holds model, prompt id, non-secret call settings and source hashes. Only sources
explicitly marked public include title/URL/licence; Studio-only sources export hashes alone.
No database integer ids, person records, instructions, excerpts, raw candidates or credentials.
Use canonical JSON for fingerprints and a deterministic writer. No provenance file is written
for an ordinary node with no origins. Old nodes continue to read without it.

**Private proposal:** public UUID, draft FK, nullable requesting/applying user, protected base
revision, target descriptor, optional figure-copy digest, instruction, source/candidate snapshots,
prompt version, state, gateway call, raw and replayed candidate, conflict/finding report,
started/deadline timestamps and protected accepted revision. Records preserve evidence; a
deleted requester makes unstarted work refuse, rather than becoming an anonymous model call.

**States:** queued → running → ready, or refused/failed. Ready can become accepted/discarded.
Conflicts are a report on ready, with acceptance blocked until resolved. Duplicate execution is
a no-op after the queued claim. Interrupted running jobs are failed after their deadline; they
are never re-enqueued automatically. This guarantees one gateway invocation per proposal,
not exactly-once billing at an outside provider.

**Origins:** revision-local mappings carry accepted receipts and their private raw AI baselines.
Transform them from explicit edit operations, including the writer's normalization; never infer
authorship with Review's similarity matching. Shared figure files propagate to all affected review
items. Combined text retains all contributing origins; an ambiguous combined/missing baseline
requires an explicit resolution instead of choosing one old AI output as if it owned the whole.

**Requests:** a client-generated idempotency UUID, kind, target, exact `based_on`, instruction,
source snapshots and candidate references; a figure request also includes its current unsaved
text/component and digest. Source/candidate ids are validated against the captured request.
Replies contain one typed operation for that target and source ids, never arbitrary tools/code.

**Diagnostics to declare with tests:** CA0500 unsupported target/operation; CA0501 invalid source
or candidate reference; CA0502 invalid candidate content; CA0503 unresolved replay conflicts;
CA0504 ambiguous/missing origin baseline; CA0505 interrupted work; CA0506 changed figure working
copy; CA0507 invalid proposal transition; CA0508 unavailable prompt version. Gateway refusals
retain CA04xx; stale/not-open/auth retain existing CA02xx/CA01xx behavior. CS1200 invalid JSON;
CS1201 invalid public format/fields/version; CS1202 invalid target/fingerprint; CS1203 invalid
receipt/source references. Do not allocate unused diagnostics beyond these cases.

## Review focus

1. **Origins through normalization:** moves/duplicates/adjacent text and shared figures cannot
   swap or lose authorship; no positional similarity inference.
2. **Human corrections through multiple generations:** the raw AI baseline is distinct from
   the human-applied revision; identical changes deduplicate, overlapping changes never guess.
3. **No long transaction around a provider:** duplicate workers, broker errors, termination,
   late results and exact-revision acceptance have explicit tested outcomes.
4. **Figure edits exist outside Postgres:** current-copy digest and server revision are separate
   checks; Save is the only point where a candidate enters content and gets its receipt.
5. **Public/private boundary:** sidecars, index, content responses and landing metadata cannot
   export private receipts; imported history never pretends the original private call still exists.

The riskiest checkpoint is Step 3–4. If tests show the approved mapping/replay semantics cannot
be implemented conservatively, stop with a concrete protocol issue and options; do not silently
weaken provenance or expand into a general merge/editor platform.
