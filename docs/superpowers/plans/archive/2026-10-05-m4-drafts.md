# M4.4 — Drafts, the content API, and checks: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this
> plan task by task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** A team member opens a draft of a node (one open draft per node), edits it through a
content API whose every save is validated by `code-schema` exactly as CI validates the files, and
checks it against the graph and M4's bar. No screens, no AI, no review or landing.

**Architecture:** The index is a read model; a draft is a working copy of a node's three files,
snapshotted per save. Edits are pure functions in `code_schema.edits`; a save parses the latest
revision, applies an edit, writes the files, reads them back, and stores a revision or refuses.
A new Django app, `code_api.studio`, holds `Draft`, `Revision`, the save and the API.

**Tech stack:** Python 3.14, Django 6.1, Django Ninja, pytest, mypy strict. The web app changes only
its generated `schema.ts`.

**Spec:** `docs/superpowers/specs/2026-10-05-m4-drafts-design.md` (M4W.0–M4W.6), issue #122.

## Global constraints

- **One parse path.** A draft is validated by `code-schema`'s own functions with the index's
  regions and providers; nothing in `apps/api` re-implements a format rule.
- **Pure packages stay pure**: `code_schema.edits` imports no Django (the purity guards; declare
  the new module in `tests/guards/purity.py` if the guard asks).
- **`code-schema`'s messages, codes, lines and order do not change.**
- **Learner routes and their responses do not change.**
- Error bodies are `Message(detail, code)`; draft codes take `CA0200–CA0299 · drafts`, each named
  by a test; the reference page is regenerated.
- **Before every push, run the Python steps with CI's `env:`** (`CODE_ALLOWED_HOSTS=localhost`,
  the CI secret key, `CODE_DEBUG=false`) against the local Postgres (:5433) and Redis (:6380).
  Watch CI without blocking.
- Postgres and Redis run under podman; web commands run in `node:24-alpine` under podman, one
  `npm` command per run. Never run the API tests while a reviewer runs them.

## Review focus

- Task 1's round trip: index → `Node` → files byte for byte, for every fixture.
- Task 4's save: the stale-revision check, the one-open-draft constraint under a race, and that a
  refused save stores nothing.
- The fresh-reviewer checkpoint is after Task 4; the final review is over the whole branch.

### Task 3: Edits as pure functions (M4W.3)

**Files:**
- Create: `code_schema/edits.py`; `tests/schema/test_edits.py`.

**Interfaces** (each `Node` in, `Node` out; a position out of range or a missing id raises
`EditError` with a sentence):
- `set_fields(node, **fields)`; `set_links(node, kind, links)`; `set_resources(node, resources)`;
- `insert_block(node, at, block, question=None)` (a `Try` block requires its `TryQuestion`),
  `update_block(node, at, block, question=None)`, `move_block(node, at, to)`,
  `delete_block(node, at)` (deleting a `Try` block deletes its question);
- `add_exam_question(node, question)`, `update_exam_question(node, question_id, question)`,
  `delete_exam_question(node, question_id)`.

  never mutate their input.
- [x] **Step 2: Run.** Expected: fail.
