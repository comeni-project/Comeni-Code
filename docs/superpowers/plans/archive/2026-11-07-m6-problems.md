# M6.7 Problems, the ground — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A node may hold one Rosalind-shaped problem (`problem.yaml` placed by `:::{problem}`),
generated, solved and checked by a pure `code-problems` kit, proved by a 20-seed self-test inside
validation, and carried through the index, drafts, review and landing.

**Architecture:** `packages/code-problems` holds kits (Strategy: `cost`, `generate`, `solve`,
`check`, `MISTAKES`, `MAX_BYTES`, a params schema), its own PRNG and `self_test`, which returns
findings with CS1101–CS1105 as `code-figures` does. `code-schema` reads the file and its block,
runs the self-test once per file text, and owns CS1106–CS1111. The API stores a `NodeProblem`, a
draft carries `problem_yaml`, review keys it, landing writes it; the learner API omits the block.

**Tech Stack:** Python 3.14 (pure packages), Django + Ninja; React/TypeScript for one workbench row.

**Spec:** `docs/superpowers/specs/2026-11-07-m6-problems-design.md` (M6PR.1–M6PR.7), #334.

## Global Constraints

- Codes exactly as M6PR.5: CS1101–CS1105 written by `code-problems` (concern `problems`),
  CS1106–CS1111 by `code-schema`; each in `diagnostics.yml` with `explain`, named by a test; then
  `uv run code-schema diagnostics --write docs/reference/diagnostics.md`.
- `code-problems` imports only `__future__`, `collections.abc`, `dataclasses`, `json`, `pathlib`,
  `typing`, `code_figures.schema`, `code_figures.findings` (its allowlist in
  `tests/guards/purity.py`, watched failing on a planted `import random` first).
- PRNG: splitmix64 (`state += 0x9E3779B97F4A7C15; z = state; z = (z ^ z>>30) * 0xBF58476D1CE4E5B9;
  z = (z ^ z>>27) * 0x94D049BB133111EB; z ^= z>>31`, all mod 2⁶⁴). Never `random`.
- Params bounds (M6PR.2): `de-bruijn-edges` k 3–12, genome 7–5,000, read (k+1)–150 (schema: 4–150,
  CS1101 checks read > k in the kit), coverage 1–30, errors 0–0.02; `count-kmers` k 2–12, genome
  `[min, max]` each 7–5,000, the rest the same.
- One problem per node; the sample is computed from `sample.seed` and `sample.params`.
- CS1105: at least 18 distinct answers among seeds 0–19; the sample not counted.
- No learner endpoint sends a problem; no TypeScript twin.

## Review Focus

1. **Generation at the bounds** (k = 12 with read = 13; genome = 7; coverage = 1): no crash, no
   empty dataset, the solver's answer accepted — `test_kits.py::test_each_kit_at_its_bounds`.
2. **Answers typed loosely** (CRLF line ends, trailing spaces, a final blank line, `A->B` without
   spaces): CRLF and spaces are forgiven, `A->B` is a wrong format named in `said`, never a crash —
   `test_kits.py::test_a_given_answer_is_read_loosely`.
3. **A cost over the limit is refused before anything runs** (genome 5,000, coverage 30, read 150
   past `MAX_BYTES`): CS1102 and `generate` never called — `test_self_test.py::
   test_cost_is_checked_before_generating`.
4. **The same file validated twice in one process runs the self-test once** (the cache), and a
   changed text runs it again — `test_problem_file.py::test_the_self_test_runs_once_per_text`.
5. **A problem block deleted through `/blocks`** is CA0205 and the file stays; a move keeps it —
   `test_problem_api.py::test_the_problem_block_is_not_deleted_through_blocks`.
