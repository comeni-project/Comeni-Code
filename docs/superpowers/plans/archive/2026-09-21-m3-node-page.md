# M3 part 5, the Node page: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this
> plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `/node/<id>` shows a node as the published L5 board draws it: its resources under
*Learn it* (a video really playing), its try questions in the body, the links around it, and
the route strip when it was opened from a route.

**Architecture:**
- `code-schema` gains a resource's `video` and a provider's `players`.
- The index and `GET /api/nodes/{id}` carry `video`.
- The web app gains `src/node/`:
  - pure helpers (`body.ts`, `embed.ts`), tested alone;
  - a component per board piece (`LearnIt`, `TryQuestion`, `RouteStrip`, `Aside`);
  - `NodePage`, which composes them, reading the node and, with a goal, the cached route.

**Tech stack:** Python 3.14 with pytest, ruff and mypy; Django with Ninja; React 19 with
TanStack Query and React Router; `react-markdown` with `remark-gfm`; Tailwind 4; vitest and
Testing Library; Biome.

**Spec:** [`2026-09-21-m3-node-page-design.md`](../specs/2026-09-21-m3-node-page-design.md)
(M3P5.1 to M3P5.7).

## Global constraints

- **The reference is the published canvas**, https://claude.ai/artifact/WGDwxV8gHZwSxyzSQAJKPa,
  L5. Each screen task ends with a look in Chrome beside it, light and dark, at 1440 and at a
  phone's width.
- **Nothing learner-shaped is faked:** no progress, no *answered*, no review dates, no *Not yet
  reviewed*.
- **No author HTML reaches the page.** `react-markdown` runs with `skipHtml`, and there is no
  `dangerouslySetInnerHTML`.
- **Tests use `tests/fixtures/`**, never the content repo.
- **Every commit passes its layer's checks:** `uv run ruff check . && uv run ruff format --check .
  && uv run mypy && uv run pytest` for Python, and `npm run lint && npm run typecheck && npm test
  && npm run build` in `apps/web` (Node 24) for the web.

### Task 1: `video` and `players` in the node format

**Files:**
- Modify:
  - `packages/code-schema/src/code_schema/providers.py`
  - `packages/code-schema/src/code_schema/resources.py`
  - `packages/code-schema/src/code_schema/writer.py`
  - `tests/fixtures/salmon/providers.yaml`
  - `tests/fixtures/salmon/algorithms/de-bruijn-graphs/node.yaml`
- Test: `tests/schema/test_resources.py`, `tests/schema/test_providers.py`,
  `tests/schema/test_writer.py`

**Interfaces (produced):**
- `Provider(id, name, licences, embed, players: tuple[str, ...] = ())`
- `Resource(..., part="", video="")`
- `PLAYERS = {"youtube": re.compile(r"[A-Za-z0-9_-]{11}")}`

**Steps:**
- [ ] **Write the failing tests.**
  - `players: [youtube]` parses to `("youtube",)`, and a missing `players` is `()`.
  - `players: [vimeo]` is a problem: *vimeo is not a player (youtube)*.
  - A video with `video: youtube:Jnk_4Maf5Fk` parses, with `video == "youtube:Jnk_4Maf5Fk"`.
  - These are each one problem, on the right line:
    - a video with `display: embed` and no `video`: *an embedded video names the video it
      plays, such as video: youtube:<id>*;
    - `video` on a reading: *only a video names a video to play*;
    - `video: vimeo:123`: *Khan Academy is not embedded through vimeo*;
    - `video: youtube:short`: *short is not a youtube video id*;
    - `video: Jnk_4Maf5Fk`, with no player: *a video is written player:id, such as
      youtube:Jnk_4Maf5Fk*.
  - The writer round-trips a resource with `video` byte for byte, and writes `video` after
    `url`.
  - Update the tests' `VIDEO` text to carry `video: youtube:Jnk_4Maf5Fk`, and the `PROVIDERS`
    in those tests to give Khan Academy `players=("youtube",)`.
- [ ] **Run them:** `uv run pytest tests/schema -q`. Expect failures on the new tests.
- [ ] **Implement.**
  - `providers.py` reads an optional `players` list and checks each entry against `PLAYERS`.
  - `resources.py` adds `video` to `_KEYS` (after `url`) and checks it: the form, then the
    kind, then embed-needs-video. It then checks the player against the registry in
    `_registry_problems`.
  - `writer.py` writes `video` after `url` when there is one.
- [ ] **Update the fixtures.**
  - `providers.yaml`: Khan Academy gains `players: [youtube]`.
  - `de-bruijn-graphs/node.yaml`: the video gains `video: youtube:Jnk_4Maf5Fk`, and loses
    `part: 2:10–7:45`, because the real video is 4:41 (M3P5.3).
  - Run `uv run code-schema validate tests/fixtures/salmon`. Expected: clean.
- [ ] **Run the Python checks.** Commit as `feat(schema): a video resource names the video it
  plays`.

### Task 3: reading a node, and the pure helpers

**Files:**
- Create:
  - `apps/web/src/api/nodes.ts`
  - `apps/web/src/node/body.ts` and `body.test.ts`
  - `apps/web/src/node/embed.ts` and `embed.test.ts`
- Modify: `apps/web/src/api/client.test.ts` (the node URL)

**Interfaces (produced):**

```ts
// api/nodes.ts
export const nodeUrl = (id: string) => `/api/nodes/${encodeURIComponent(id)}`;
export const fetchNode = (id: string, signal?: AbortSignal) => getJson<NodeOut>(nodeUrl(id), signal);
// node/body.ts
export type Piece = { kind: "text"; markdown: string } | { kind: "try"; id: string };
export function splitBody(body: string): Piece[];                 // on ^\s*{% try id %}\s*$ lines
export function headingsOf(body: string): { id: string; text: string }[]; // ## lines, outside fences
export function slugOf(text: string): string;                    // "The problem it solves" → "the-problem-it-solves"
// node/embed.ts
export function playerSrc(video: string, part: string): string | null; // youtube → youtube-nocookie with start/end
export function withRoute(path: string, goals: string[], known: string[]): string;
```

**Steps:**
- [ ] **Write the failing tests.**
  - The de Bruijn body splits into text, try `kmers-per-read`, text, try `shared-unitig` and
    text.
  - A body with no marker gives one piece.
  - A `{% try x %}` inside a fenced block is left alone.
  - `headingsOf` finds `Further reading` and skips a `##` inside a fence.
  - `slugOf` produces lower-case hyphenated slugs.
  - `playerSrc("youtube:Jnk_4Maf5Fk", "")` is
    `https://www.youtube-nocookie.com/embed/Jnk_4Maf5Fk`.
  - With `"2:10–7:45"` it carries `?start=130&end=465`.
  - An unknown player gives `null`.
  - `withRoute("/node/k-mers", ["salmon"], ["tpm"])` is
    `/node/k-mers?goal=salmon&known=tpm`, and with no goals it is the bare path.
- [ ] **Implement them. Run `npm test`.** Commit as `feat(web): reading a node, its body's
  pieces and its player`.

### Task 4: a try question

**Files:** create `apps/web/src/node/TryQuestion.tsx` and `TryQuestion.test.tsx`.

**Interface:** `TryQuestion({ question: QuestionOut, number: number })`.

**Steps:**
- [ ] **Write the failing tests**, using de Bruijn's two questions.
  - It starts collapsed. It shows its number, the ask and *1 min · a count*, and *Try it* has
    `aria-expanded="false"`.
  - **Opened, a number question:**
    - it has a number field and *Check*;
    - `5` shows *Right — 5. Why:* and the rationale;
    - `6` shows *Not quite*, with no rationale;
    - a second wrong answer shows the rationale.
  - **Choice:** clicking `TTGCA` shows *Not quite*, and `ACGTTG` shows *Right — ACGTTG*.
  - *Show a hint* gives *Hint 1 of 2 used* and the first hint. A second click gives the
    second hint, and then the button is gone.
  - *Show the answer* shows the rationale.
  - A number with `tolerance` accepts `answer ± tolerance`.
- [ ] **Implement** in the board's style:
  - collapsed: a bordered row with a numbered square and *Try it ⌄*;
  - opened: a `border-sel` panel with option buttons (`✓` on the chosen right one) or the
    field;
  - the hint chip, and the green rationale box.
- [ ] **Run `npm test`.** Commit as `feat(web): a try question, with its hints and why`.

### Task 6: the Node page

**Files:**
- Create:

  - `apps/web/src/node/NodePage.test.tsx`

  - `apps/web/src/route/RoutePage.test.tsx`
  - `apps/web/package.json` and its lock: `react-markdown`, `remark-gfm`, pinned

**Steps:**
- [ ] **Write the failing tests**, using `debruijn.fixture.ts` and `SALMON`.
  - **The top of the page:**
    - the `h1` is *de Bruijn graphs*;
    - the breadcrumb is *Algorithms › de Bruijn graphs*;
    - the level tag reads *Intermediate*, and *About N min* adds one per question;
    - *What you'll be able to do* holds the claim.
  - **Needs:** *Before this, all of:* has a chip per need, linking with the route kept. A need
    in `known=` carries a tick.
  - **Body and questions:**
    - the body renders its `##` headings as `h2` with ids;
    - a `<script>` in a body is not rendered;
    - both questions sit where their markers are, after the fenced block and before
      *Further reading*.
  - ***On this page*** lists *Learn it* and the headings, linking to their ids.
  - **Side column:** *Goes deeper*, *Related* and *Needed by* are there, each row with
    *level · N min*. An empty group is absent.
  - **The strip:**
    - with `?goal=salmon`, it reads *On your route to Salmon*, the region's line, *stop N of
      17* and *unlocks …*;
    - *Back to the route* goes to `/route?goal=salmon&stop=<id>`;
    - off the route, it says *Not on your route to Salmon*;
    - with no goal, there is no strip.
  - **States:** a 404 prints the API's sentence. With no resources there is no *Learn it*,
    and *On this page* omits it.
  - **The Route page:** *Open page* is `/node/k-mers?goal=salmon`, and carries `known` when
    there is one.
- [ ] **Implement.**
  - `NodePage` reads `useParams().id`, `goal` and `known`.
  - The node query is `["node", id]`. The route query is the Route page's own
    `["route", goals, known]` key, enabled only with goals.
  - The grid is `lg:grid-cols-[180px_minmax(0,1fr)_260px]` at the board's 1440 frame.
  - *On this page* is sticky, and marks the section in view with an `IntersectionObserver`,
    guarded for jsdom.
  - `Body` maps `splitBody` pieces to `<Markdown skipHtml remarkPlugins={[remarkGfm]}
    components={…}>` or `<TryQuestion>`, numbering questions in order.
- [ ] **Run all web checks.** Commit as `feat(web): the Node page, beside the L5 board`.
