# M5.1 — The gateway and the AI settings: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** one door to models (`code_api.ai`), connections and per-site settings an operator manages
in Studio's AI page, every call recorded, and nothing calling a model when nothing is configured.

**Architecture:** a Django app `code_api.ai`: `sites.py` (the fixed call sites), `models.py`
(`Connection`, `SiteSetting`, `AICall`), `secrets.py` (Fernet), `resolve.py` (site → model or
refusal), `gateway.py` (`call`, through one replaceable transport), `chatgpt.py` (the token and the
sign-in), `api.py` (Studio routes, operators). The web gains `studio/ai/` with Models and Usage.

**Tech Stack:** Django Ninja, Celery-free (the page drives the sign-in), Redis (locks, the sign-in
attempt), LiteLLM 1.105.1 (pinned), `cryptography` (Fernet, already locked), React, TanStack Query.

**Spec:** `docs/superpowers/specs/2026-11-13-m5-gateway-design.md` (M5G.1–M5G.9). Issue #446.

## Global Constraints

- Only `code_api.ai` imports `litellm`; LiteLLM is pinned `==1.105.1` in `apps/api/pyproject.toml`.
- Every LiteLLM call passes `api_key` and `api_base` explicitly (`None` where none).
- Settings come from `CODE_*`: `CODE_AI_MODEL`, `CODE_AI_API_KEY`, `CODE_AI_BASE_URL`,
  `CODE_SETTINGS_KEY`, `CODE_AI_CHATGPT_DIR` (an empty value is unset). `env.py` sets
  `os.environ["CHATGPT_TOKEN_DIR"]` from the last, once, with a comment.
- No response ever carries a key or a token; a key reads back as `set` and its last four characters.
- No prompt or reply text in `AICall`.
- Caps count calls in the current UTC day, from `AICall`.
- Codes CA0400–CA0407 (band *AI*), as M5G.8 words them.
- The AI page is operators only; copy from the boards (`AISettings`, `AISignIn`, `AIUsageM5`).
- Tests never reach a provider: the gateway's transport is replaced; ChatGPT HTTP is faked.

## Review Focus

1. **Two processes refreshing the ChatGPT token at once**: one refresh under the Redis lock, the
   other reads the fresh file (Task 4 test with two threads).
2. **A key in the host's environment** (`OPENAI_API_KEY`) with a hosted connection that has none:
   never used (Task 3 test).
3. **A connection removed while a site points at it**: the site resolves to *no model* with its
   sentence, the page shows it (Task 3, Task 6 tests).
4. **`CODE_SETTINGS_KEY` changed after keys were stored**: the key cannot be read; the connection
   says so (*re-enter the key*), never a 500 (Task 2 test).
5. **A sign-in attempt left behind** (the page closed mid-wait): it ends after 15 minutes; a new one
   starts cleanly (Task 4 test).

### Task 3: Resolve and call

**Files:** `code_api/ai/resolve.py`, `gateway.py`; tests `apps/api/tests/ai/test_gateway.py`.

**Interfaces:**
- `Route(connection: Connection | None, model: str, api_key: str | None, api_base: str | None,
  temperature, reasoning_effort, timeout)` — `connection` None for *From .env*.
- `resolve(site: str) -> Route | Refused` (`.env`'s model locks *default*; *same as default*
  follows it; a removed connection or no connection → `Refused("CA0400", <sentence>)`).
- `Transport = Callable[[Route, list[dict]], Completion]` (`text`, `tokens_in`, `tokens_out`,
  `cost`); `LITELLM: Transport` calls `litellm.completion(model, messages, api_key=…, api_base=…,
  …)`; `gateway.transport` is the module attribute tests replace.
- `call(site, messages, *, by: User | None, reply: type[BaseModel] | None = None, draft: UUID |
  None = None, prompt_id: str) -> Reply | Refused`; `Reply(text, value, call_id)`.
- Caps: `AICall` rows of the site today (UTC) with outcome `answered` ≥ cap → `Refused("CA0404")`,
  recorded as `capped`. Provider errors → `Refused("CA0405", their words)`, `failed`. A reply not
  the model → `Refused("CA0406")`.

- [ ] **Step 1: Failing tests**: no connection → CA0400, nothing recorded; `.env` model resolves for

  transport gets `api_key=None` and LiteLLM is asked with it explicitly (Review Focus 2, the real

### Task 4: The ChatGPT token and the sign-in

**Files:** `code_api/ai/chatgpt.py`; tests `apps/api/tests/ai/test_chatgpt.py`,
`apps/api/tests/ai/test_litellm_private.py`.

**Interfaces:**
- `fresh_token() -> str | Refused` — reads `auth.json`; none → CA0403; expired → refresh under the
  Redis lock `ai:chatgpt:token` (re-read after taking it), `_refresh_tokens` + `_build_auth_record`
  + atomic write; refresh fails → `Connection.ran_out = True`, CA0403. The gateway calls it before
  every `chatgpt/` call.
- `start() -> SignIn(user_code, link, expires_at)` — `_request_device_code`; the attempt in Redis
  `ai:chatgpt:attempt` for 15 minutes (a new start replaces it).
- `poll() -> "waiting" | "signed-in" | Refused` — one POST to `CHATGPT_DEVICE_TOKEN_URL`; approved →
  `_exchange_code_for_tokens`, the record written atomically under the lock, the connection added
  or renewed (`ran_out` false) and tested; no attempt or past 15 minutes → CA0403.
- `write_atomically(path, data)`: a temporary file in the same folder, `os.replace`.

- [ ] **Step 1: Failing tests** (httpx faked with `respx` or a fake `_get_httpx_client`): no token →
  CA0403 and LiteLLM never called; an expired token refreshed once by two threads (Review Focus 1);
  a failed refresh marks `ran_out`; start answers the code and LiteLLM's link; poll waiting /
  signed-in / expired (Review Focus 5); the private-method test: each method and constant exists and
  `_request_device_code` returns `device_auth_id`, `user_code`, `interval` (on the pinned version).
- [ ] **Steps 2–4.** **Step 5: Commit** `feat(api): the ChatGPT sign-in, driven by the page, its token owned by Code (#446)`.
