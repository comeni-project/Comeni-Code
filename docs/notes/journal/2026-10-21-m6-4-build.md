## Decisions, and why

- **A figure that fails is refused at save**, not saved with a problem: a stored file never holds
  errors, and the last good file stays. So Checks never lists a figure's own problems; the
  refusal names each by code and data path.
- **A figure's file goes with its last placement**: deleting the only block or stem that places it
  deletes the file. Otherwise deleting TPM's exam question left an unplaced table and every later
  save was refused (CS1021).
- **A chart colours at most three series**: only violet, orange and magenta passed the colour-blind
  checks on both surfaces once the colour law's hues are left out.
- **The chart is drawn as the board draws it** (#371): series coloured in the data's order, lines
  of named series named at their ends with hollow points, a horizontal grid, the y title level.
  These are the renderer's, around the author's data; an author who gives a sort or a legend
  keeps it.
- **`form-action` is left out of the CSP**: it would block the GitHub sign-in redirect.

## Traps

- **A remote-debugging port may already be someone's**: a headless Chrome left by another session
  held 9333, and a driver that assumes its port attaches to that browser. Start Chrome with
  `--remote-debugging-port=0` and read `DevToolsActivePort`.
- **Vite's `strictPort` fails if the port is taken, but a check that only asks "does it answer?"
  passes** against whatever holds it. Check who listens (`ss -ltnp`).
- **A chain ending in `| tail` or `| grep` exits with that command's status**: `pytest … | tail &&
  git commit` commits a failing run. Keep each check's own exit code.
- **The stack's fixture copy is root's** (`/tmp/salmon` in the api container): copy it to edit it,
  and rebuild the index from the original after.
