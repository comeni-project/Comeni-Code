## Decisions made, and why

- **Finish M5.1, not the entire M5 phase**, as the operator requested: the remaining parts still
  need their own approved specs and plans. No new product protocol was chosen here.
- **Keep #461 deferred.** It already records the prior review's minor findings; this session
  fixed the inherited #460 and three additional mechanical violations of M5.1's agreed behavior.
- **Clear call settings in the API as well as the page.** A typed hosted model and returning to
  the default skipped the page's original reset. A cap-only change preserves tuning; changing
  connection, model or default inheritance clears it. Both API and page regressions failed first.
- **Guard LiteLLM's completion boundary**, preserving tests that deliberately fake the transport
  or inspect completion arguments. `pytest.fail` cannot be swallowed by the gateway's ordinary
  exception handler. Both #460 regressions were also observed failing with the protections
  temporarily disabled; a sentinel prevented a real provider request during that check.
- **Refuse storage failures at the token/sign-in boundary.** Redis loss and an unwritable token
  folder do not become a 500 or escape to a gateway caller. Tests first reproduced Redis set,
  get, delete and token-lock failures, file-write failure and a leaked temporary token file.
