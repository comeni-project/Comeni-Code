## Decisions made, and why

The design decisions are in the spec, each with its rejected alternatives; the ones that took the
most arguing, in the order they were made:

1. ***Related* is written on both nodes.** The operator asked whether that burdens the AI; it does
   not, because models write through Studio's content API (W5.2), where one call writes both sides.
   What it buys is that any `node.yaml` shows all its neighbours. A `related.yaml` of pairs was the
   strongest alternative and lost on merge conflicts and on having nowhere for two points of view.
2. ***needs* is a list, and choices are designed, not wired.** The agent first proposed
   *any-of* entries resolved from what the learner holds; the operator asked where the system
   knows that, and the honest answer — only from stored evidence, which a new learner lacks — sank
   inference. The operator wanted optional paths kept, so both are designed in W3.2 in a form that
   never changes a route unless the learner opens it, and are refused until content asks for them.
   If *any-of* proves confusing, it is removed while that is cheap.
3. **A need is never a tool.** The agent's own first *any-of* example (*command-line basics* or
   *Galaxy basics* under *Salmon*) was wrong, and the operator caught it: operating a tool is not
   understanding a claim. Ways to run something are resources in the body.
4. **Every link has a reason.** The agent proposed reasons on *needs* only; the operator asked for
   them on all three, so the learner gets a sentence rather than a chip, and every link can be
   judged when it is proposed. It also gave every kind one shape.

**Where the build departed from the plan** — small, and none touches a message:

- The node-id check computed its message twice through an unused walrus; simplified.
- The cross-kind rule lives in a helper, `_parse_all_links`, rather than inline in `parse_node`,
  which was already the longest function in the package.
- Two tests the plan did not have: a bad link is dropped while the good ones are kept (so part 3's
  graph rules still see them), and *helps* / *any-of* are refused until wired (the spec's M1P2.3
  promise, now pinned).

## Open questions

- **How long a cycle message may be.** A cycle through twelve nodes is twelve names; part 3 decides
  whether to print the whole ring or its first few.
- **Whether a *reason* can be judged for emptiness.** *"Related to Salmon."* passes every check in
  this part. A model-scored reason check would be a new declared model site; wait for S2 to show
  the pattern first.

## Traps

- **`any-of` and `helps` appear in W3.2 but are refused by the validator.** That is deliberate: the
  design exists so nobody reinvents it, and the refusal exists so no content depends on rules that
  are not built.
- **`goes-deeper` in YAML, `goes_deeper` in Python.** The writer maps one to the other in `_LINKS`;
  a new link kind must be added to `LINK_FIELDS`, `Node`, `_parse_all_links`' caller and `_LINKS`.
- **The cap of four counts every entry**, broken ones included, so fixing an entry never makes the
  cap message appear or vanish unexpectedly.
