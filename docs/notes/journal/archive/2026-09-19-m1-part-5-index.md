## Decisions made, and why

The operator's four answers, each with its rejected alternatives in the spec:

1. **All or nothing** (M1P5.2): a folder with any problem changes nothing. Skipping broken nodes
   would silently shorten routes.
2. **Everything else names a node by its id string** (M1P5.3), never a foreign key into the index,
   so the index is disposable and a content edit never touches learner data.
3. **The index holds bodies** (M1P5.4). The operator: bodies read from disk may come back *"if we
   need later for a more distributed system … for the mvp we stay simple"*.
4. **A row per attempt, applied or refused** (M1P5.5), so a background refusal is never invisible.

**The operator's scaling note** (M1P5.7): *"this is ok for the mvp, but this wont scale, once we
got to a central database we got to change this! but that will be A LOT down the line."* The spec
records what should survive that change: id references, and never showing a half-applied change.

**Corrections made while planning**, in the spec before any code:

- **No admin test.** The spec had *the models are not in the admin*; the admin is not installed,
  so the test could not fail. The claim is kept as a fact, not a test.
- **The dump covers three tables.** Builds differ by design between rebuilds and are checked alone.
- **Text columns have no length limits.** The validator owns `title` ≤ 80 and `claim` ≤ 200; a
  second copy as column sizes would turn a clean rebuild into a database error the day they differ.

**Where the build departed from the plan:** the generated migration needed `ruff format` (as the
accounts migration did), and the suite has 277 tests, not the plan's 273 — the link check has one
test per Markdown file, and this branch adds four.

  merge that is years of tiny rows. Decide when the worker exists.

## Traps

- **Django's foreign keys are checked at commit, not at insert** (Postgres `DEFERRABLE INITIALLY
  DEFERRED`). A test never commits, so a broken apply shows up at teardown as an error, not in the
  test body. The rebuild never applies a folder with problems, so production never meets it.
- **The advisory lock is not tested** (M1P5.6): it is the one line guarding two concurrent
  rebuilds. Read it when reviewing `index.py`.
- **Tests need Compose's Postgres.** Start it before trusting a red run.
- **`rebuild_index` is the only writer.** A test's own deletes (to simulate an empty index) are
  setup, not a second writer; application code must never write these models.
