## Decisions made, and why

- **The forms list follows what the parsers do, not the spec's examples.** `1:30` and `~` read
  alike on both sides (since #376 the server keeps `1:30` as text), so they stay allowed; `<<` and
  `=` read apart, so they are refused. 012, 0x1f, .inf and .nan were CS1011 in a number column;
  now CS1023 wherever they are.
- **The server refuses a key written twice.** PyYAML keeps the last; YAML 1.2 refuses. Without
  this, a file could pass on the server and fail in the composer.
- **Untouched lines are kept by line, not by the Document alone** (#385). `yaml` re-spaces a
  trailing comment, so an edit keeps every line it did not change from the file as written. A file
  the Document would change in more than such spacing (or that ends in a comment) opens as YAML,
  saying why, rather than being rewritten.
- **Quoting is decided afresh on each write**, in the old quote's style when quotes are still
  needed. Keeping a value's quotes for good meant a trailing space typed mid-word left it quoted.
- **A bad add (both text and component, or neither) is 422 CA0205**, the existing edit refusal,
  not a new 400.
- **Settings are rows per key** (#386), a group of groups (a chart's encoding) giving each group a
  row; a key inside a channel is removed in Edit as YAML or by removing the channel.
