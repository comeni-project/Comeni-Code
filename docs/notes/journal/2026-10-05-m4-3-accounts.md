# 2026-10-05 — M4.3, accounts, invites and roles

## Where things stand

- **M4.3 was designed with the operator in conversation, then built.** The spec and plan were
  merged in PR #153; the build is on `feat/m4-3-accounts`, sub-issues #154–#160 of #121.
- **Checked.** 703 Python and 231 web tests pass, with mypy, ruff, Django's checks, the migration
  check, `collectstatic`, the web build and `nginx -t`. By hand against a dev server:
  `invite_operator` printed a link; the lookup, the accept, a password sign-up with CSRF,
  `/api/me` as operator and the team list all answered; the reused link was refused with CA0106.
- **GitHub sign-in is tested only with GitHub mocked.** No OAuth app is registered; until
  `CODE_GITHUB_CLIENT_ID` and its secret are set, GitHub is off.

- M4.3.4: invites, hashed tokens, and sign-up only through one (CA0103–CA0107);
  `manage.py invite_operator`.
- The checkpoint review (#161): the invite's address verified and the only one; password reset's
  web routes; JSON 403s on a lost race; 401 before CSRF; the cache in Redis; a lock when minting.
- M4.3.5: GitHub sign-up through an invite, taking its address and role.
- M4.3.6: the team API, with the last operator protected (CA0108, CA0109).
- M4.3.7: `/_allauth` in both proxies, with a test; `Referrer-Policy: same-origin` in nginx; allauth's
  payloads name a user by `public_id` (#162, found by hand).
- The final review (#163): nginx's `Host` lacked the port, so every write through the Compose stack
  failed CSRF; team changes could deadlock; GitHub's pending sign-up form spent the invite twice;
  accepting an invite now needs the CSRF token (CA0110).

## Decisions, and why

All are in the spec with what was rejected: ranked roles, one per person (operator's choice);
the invite link decides, for password and GitHub alike (operator's choice); allauth headless
beside our own Ninja routes (operator's choice). Made during the build:

- **Django 6.1's `MAILERS`, not `EMAIL_BACKEND`**, which 6.1 deprecates.
- **GitHub's callback at `/_allauth/accounts/`**, so the proxies forward one prefix.
- **One address per account, verified at sign-up** (#161). Changing one's email is out of M4.3, and
  allowing a second address let a member swap their email for an unclaimed one.
- **The cache is Redis**, so allauth's rate limits count across workers; tests get a local cache
  each, so no run's counts reach another.
- **allauth ships no types**: mypy treats `allauth.*` as untyped there only.

## Traps

- **nginx's `$host` drops the port**: Django's CSRF origin check then refuses every write behind
  it. Pass `$http_host`. `stack-check.sh` makes no writes, so only a test catches it.
- **allauth validates a sign-up's input before asking whether sign-up is open**, so a check in
  `clean_email` must not refuse when no invite is held, or the answer is 400 instead of 403.
- **allauth's social sign-up calls the social adapter's `save_user`**, never the account adapter's.
- **Web commands run in `node:24-alpine` under podman** with `--userns=keep-id` and `:Z` on the
  volume, one `npm` command per run; `npm ci` first on a fresh checkout.
- **`makemigrations` can stop at an interactive question**; run it with `--noinput`.
