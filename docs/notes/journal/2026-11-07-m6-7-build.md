## Decisions made, and why

The ledger's rulings, each kept against the spec:

- **`MAX_BYTES` is 120,000**, not 600,000: with the schemas' bounds a dataset never passes about
  187 KB, so 600,000 could never refuse; 120,000 refuses genome 5,000 × coverage 30 at read 150.
- **`problem.yaml` is kept as written** and edited whole, as figure files are, not re-written by
  a canonical writer (the spec said one): no edit changes one field, so a writer could only
  rewrite an author's file.
- **The `Rng` keeps its seed**, so `generate(params, rng)` names the dataset (`<kit>-<seed>.txt`)
  without a wider signature.
- **Studio's schema is `NodeProblemOut`** (`ProblemOut` already names a validation problem);
  `ProblemBlockOut` joins the shared block union, and the learner's API filters the block out.
- **Tests that pinned `:::{problem}` as refused** (CS0413) now pin `:::{claim}`, still refused.
- **CS1105 caught a real limit while testing**: a 3-mer count saturates at 64, so `count-kmers`
  needs a larger k to differ between learners; its test uses k = 8.
